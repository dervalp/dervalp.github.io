## The question, in plain words

The spec names the v5 CV as the document to publish, but newer CV versions (v7, v8, v9 and a Vertuoza and Omni-loop edition) sit beside it. Which one should the public download serve?

## The decision, in plain words

The site now serves the v5 CV the spec names, unchanged, at the same download link. The newer versions were left aside.

## The intro, for fun

Five CVs walk into a download folder, and only one gets the public link.

## The punchline, for fun

The spec picked v5, so v5 got the job. The others are still waiting by the phone.

## The options, in plain words

A. Keep the v5 CV the spec names (what was built).
B. Publish v9, the newest executive version, and recheck the About page against it.
C. Publish the Vertuoza and Omni-loop edition and recheck the About page against it.

## What I had to decide

Confirm v5, or name the newer file to publish instead; swapping it is a one-file change at the same link.

## What I did meanwhile

The public download serves the v5 CV, two pages, with the phone and email it already carried.

## What it costs to change later

Replacing the file later costs one commit and a redeploy; the link and the About page stay the same.
